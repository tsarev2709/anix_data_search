# Досье компании: закупки, арбитражи и ТЗ (AND-26)

При каждом `research`, `research-company` и этапе исследования в `daily` автоматически выполняется отдельная закупочная разведка. Она не меняет режим записи контактов в CRM. Результат сохраняется в существующий JSON `research_trace.procurement`, показывается в деталях компании на панели и в Markdown/JSON отчёте. Миграция БД не нужна.

## Что собирается

- Площадки: ЕИС `zakupki.gov.ru`, B2B-Center, Фабрикант, Росэлторг, Tender.pro, ТЭК-Торг, ЭТП ГПБ.
- Судебные источники: `kad.arbitr.ru`, `ras.arbitr.ru`; `sudact.ru` — только вторичный источник/кандидат.
- Роль исследуемой компании: заказчик/организатор, участник/поставщик, победитель, истец/заявитель, ответчик. Остальные стороны сохраняются как подписанные строки источника.
- Состояние: приём/рассмотрение, завершена, не состоялась, отменена. Только явно подписанное поле карточки устанавливает статус; меню, поисковый запрос и общие инструкции не считаются свидетельством.
- Номер закупки/дела, предмет, сумма и срок подачи, исход дела — если удалось извлечь соответствующее подписанное поле. Цены сохраняются как исходные строки; НМЦК не подменяет фактическую цену контракта или сумму взыскания.
- Ссылки на ТЗ/описание объекта закупки, протоколы и договоры. Ссылка сохраняется дословно с карточкой-источником. Индексированный PDF/DOC ТЗ можно показать как поисковую находку, без утверждения, что файл прочитан или доступен для скачивания.

## Идентификация юридического лица

ИНН берётся из отдельного поля компании/сделки amoCRM (`AMO_COMPANY_INN_FIELD_ID`, либо поле с точным названием ИНН/INN/ИНН компании). Проверяется контрольная сумма 10/12 цифр. Для точечного запуска через GitHub Actions доступен необязательный `company_inn`; в окружении — `MANUAL_COMPANY_INN`.

Если ИНН нет в CRM, проверяются уже прочитанные страницы официального домена: принимается единственный валидный ИНН рядом с названием компании. Ссылка на страницу реквизитов сохраняется в `innSource`. Внешние записи RSS и ИНН разработчика сайта не используются. При нескольких противоречащих ИНН автоматического выбора нет.

Без ИНН поиск всё равно выполняется по названию, но записи остаются кандидатами. Для подтверждения требуется прочитанная карточка первичного источника, номер процедуры/дела и совпадение ИНН в поле стороны с установленной ролью. Однофамильная компания с другим ИНН отбрасывается. ИНН в произвольном месте страницы не подтверждает чужую роль.

## Судебные дела по конкретным закупкам

Часть общего бюджета резервируется для второго прохода. После чтения подтверждённой закупки формируются запросы по её номеру к КАД/банку решений. Наблюдаемые дела связываются с закупкой только при явной ссылке на её номер или совпадении извлечённого номера договора (не короче шести символов). Для номера закупки хранится цитата; для договора — сам реквизит и ссылки на обе карточки. Это связь по реквизиту, без вывода о результате спора. Наличие у компании других дел не означает спор по этой закупке.

## Аналитика и следующие действия

Сводка считает только подтверждённую выборку: закупки по ролям/статусам, судебные дела, дела со связью по реквизиту и ссылки на ТЗ. Профиль Anix определяется по предмету/заголовку (анимация, видео, ОТ, обучение), а не по наличию слова в постороннем меню. Для активной профильной закупки предлагается проверить требования/дедлайн; для несостоявшейся — протокол и повторное объявление; для связанного спора — судебный акт и стадию.

Ноль означает отсутствие подтверждений в найденной выборке. Он не доказывает отсутствие участия, побед, несостоявшихся торгов или арбитражей. Поисковая индексация не даёт полного реестра. Полная история, динамика бюджетов, разбор PDF судебных актов и версий ТЗ — отдельные этапы бэклога.

## Ограничения и настройки

| Переменная | По умолчанию | Действие |
|---|---:|---|
| PROCUREMENT_ENABLED | true | false отключает этап |
| PROCUREMENT_QUERY_BUDGET | 16 | Общий план запросов по компании, включая второй проход; максимум 40 |
| PROCUREMENT_TAVILY_QUERY_BUDGET | 4 | Максимум базовых Tavily-запросов по компании на оба прохода; 0 отключает платный канал |
| PROCUREMENT_MAX_PAGES | 8 | Максимум попыток чтения публичных карточек; 0 оставляет только поисковые кандидаты |

Используются уже подключённые SearXNG и, при наличии ключа, Tavily. Новые аккаунты/тарифы не создаются. Бюджет этого этапа добавляется к обычному поиску контактов. Tavily для исторических закупок не ограничивается последним месяцем. Для одного публичного документа допускаются только HTTPS на доменах закупочных/судебных источников, ограничен размер карточки (1,5 MB) и время чтения, редиректы не переходятся. Файлы и архивы автоматически не скачиваются. Неизвестная разметка, блокировка и вход оставляют явную диагностику, а не выдуманные сведения.

Проверка живой страницы B2B-Center 15.10.2026: HTTP 200, но из доступного HTML не удалось установить компанию и роль; карточка не была принята за подтверждённую. В официальном интерфейсе этой площадки документация может требовать входа. КАД и остальные площадки также могут не дать карточку через публичный индекс. Прямые адаптеры и контроль полноты остаются в AND-20 и следующих задачах.
