# План усиления источников

Базовый ежедневный контур уже работает без новых ключей: SearXNG, Google News RSS, GDELT, Common Crawl, GitHub, RSS/Atom, Hacker News, Stack Exchange, публичные сайты и публичные страницы соцсетей. Новые API подключаются как дополнительные providers. Сбой одного provider не останавливает остальные.

## Приоритет 1 — можно подключить сразу

### YouTube Data API

Что добавит: свежие ролики, каналы, описания и даты по темам охраны труда, фармы, корпоративного обучения, видеопродакшна и запросам подрядчиков.

1. Создать проект в Google Cloud Console.
2. Включить **YouTube Data API v3**.
3. Создать API key с ограничением только на YouTube Data API.
4. Добавить Repository Secret `YOUTUBE_API_KEY`.
5. Запустить `monitor-demand` и проверить provider `youtube` в аудите.

Код ограничивает YouTube восемью запросами за запуск. Официальная документация: https://developers.google.com/youtube/v3/docs/search/list

### Custom field названия компании в AmoCRM

Что добавит: корректное название, когда связанная сущность «Компания» отсутствует, а название хранится в поле сделки.

1. Выполнить `npm run inspect:amo`.
2. Найти ID нужного поля сделки.
3. Создать Repository Variable `AMO_COMPANY_NAME_FIELD_ID`.
4. Запустить dry-run на одной такой сделке и проверить блок «Исходная сделка».

## Приоритет 2 — максимальный эффект для российского рынка

### Telegram через TgNinja — рекомендуемый первый шаг

Что добавит: непрерывный перехват новых сообщений из выбранных публичных чатов и каналов по ключевым фразам. Найденное автоматически пересылается в закрытую группу, откуда бот передаёт его в Supabase и панель «Спрос».

Это предпочтительнее MTProto на первом этапе: два уже имеющихся аккаунта TgNinja можно задействовать без `api_id`, `api_hash` и пользовательской сессии. По документации TgNinja один аккаунт может наблюдать до 500 групп и каналов; два аккаунта можно разделить по тематикам.

Поток: **TgNinja → закрытая группа → Telegram Bot API webhook → Supabase Edge Function → demand_signals**.

Пошаговая настройка secrets, BotFather и группы описана в [setup.md](setup.md#5-подключение-tgninja-без-mtproto). После подключения новые сигналы появляются сразу, а не только во время ежедневного GitHub Actions запуска.

Документация: https://tgninja.com/monitoring, https://edu.tgninja.com/about/instrument-perekhvat-iz-chatov-i-kanalov и https://core.telegram.org/bots/api#setwebhook

Рекомендуемое разделение:

- аккаунт 1: «ищем видеопродакшн», рекламные/имиджевые/продуктовые ролики, трансляции, тендеры и запросы агентств;
- аккаунт 2: обучающие видео, HR-бренд, внутренние коммуникации, охрана труда, промышленная безопасность, фарма и медицина.

В TgNinja используйте не одно слово «видео», а пары **намерение + решение**: «ищем подрядчика + ролик», «посоветуйте + продакшн», «тендер + видеопроизводство», «нужно обучить сотрудников + видео», «как объяснить технику безопасности», «снять кейс/интервью/вебинар», «анимация для продукта», «видео для выставки/конференции», а также варианты «смета», «бриф», «КП», «дедлайн», «исполнитель», «студия», «оператор», «монтаж».

### Telegram MTProto — второй этап

Что добавит: настоящий глобальный поиск по публичным сообщениям и каналам, а не только web-индекс `site:t.me`.

1. Создать отдельный рабочий Telegram-аккаунт для мониторинга.
2. На https://my.telegram.org открыть **API development tools**.
3. Получить `api_id` и `api_hash`: https://core.telegram.org/api/obtaining_api_id
4. Один раз авторизовать пользовательский сеанс локально.
5. Сохранить сериализованную сессию как GitHub Secret, не как файл репозитория.
6. Добавить secrets `TELEGRAM_API_ID`, `TELEGRAM_API_HASH`, `TELEGRAM_SESSION`.
7. Подключить provider на `messages.searchGlobal`: https://core.telegram.org/api/search
8. Ограничить запросы, хранить offset и выполнять инкрементальный поиск только новых публичных сообщений.

Плюсы: самое глубокое покрытие Telegram. Минусы: нужен отдельный пользовательский аккаунт, первичная авторизация и аккуратное соблюдение rate limits.

### VK API

Что добавит: поиск свежих публичных постов и чтение метаданных сообществ без зависимости от индекса поисковиков.

1. Создать standalone-приложение VK.
2. Получить токен с минимально необходимыми правами чтения публичных данных.
3. Добавить GitHub Secret `VK_ACCESS_TOKEN`.
4. Подключить `newsfeed.search` и чтение найденных публичных профилей/сообществ.
5. Сохранять ID поста, владельца, дату, текст, permalink и статистику.

Документация методов VK: https://dev.vk.com/ru/method

## Приоритет 3 — устойчивый независимый web-поиск

### Brave Search API

Что добавит: стабильный индекс, фильтры за 24 часа/7 дней/31 день и меньше зависимости от публичных SearXNG instances.

1. Создать аккаунт Brave Search API.
2. Проверить действующий тариф и лимиты в кабинете.
3. Добавить `BRAVE_SEARCH_API_KEY` в GitHub Secrets.
4. Подключить provider с freshness `pd`/`pw` и языком `ru`.

Документация: https://api-dashboard.search.brave.com/app/documentation/web-search/get-started

### Apify

Что добавит: готовые Actors для сложных JS-сайтов и соцсетей, если прямое чтение страниц перестанет работать.

1. Создать бесплатный аккаунт.
2. Получить token в Console → Settings → Integrations.
3. Добавить `APIFY_API_TOKEN`.
4. Выбрать только конкретные Actors после теста стоимости одного результата.
5. Ввести дневной бюджет и аварийный stop limit.

У Apify есть бесплатные ежемесячные credits без карты: https://docs.apify.com/get-started/agent-onboarding

## Приоритет 4 — точность контактов

### Hunter

Использовать после нахождения официального домена. Добавить `HUNTER_API_KEY`. Сначала оставить `HUNTER_VERIFY_EMAILS=false`, оценить качество Domain Search и только потом расходовать квоту на Verifier.

### LLM-классификация

OpenAI или Gemini стоит использовать не для генерации контактов, а для трёх задач:

1. классифицировать коммерческое намерение публикации;
2. связать ФИО, должность, компанию и доказательство;
3. сформировать краткий персональный повод для первого касания.

Google Search grounding в Gemini не считать гарантированно бесплатным: актуальные цены и доступность указаны на https://ai.google.dev/gemini-api/docs/pricing

## Что подключать не нужно

- Google Custom Search — закрыт для новых клиентов; официальный статус: https://developers.google.com/custom-search/v1/overview
- массовую генерацию предполагаемых email — адрес можно хранить только как `INFERRED`, но нельзя автоматически писать в AmoCRM;
- приватные чаты и закрытые профили — система работает только с публично доступными деловыми данными.

## Рекомендуемый порядок

1. Указать `AMO_COMPANY_NAME_FIELD_ID` и при необходимости ID сайта/должности.
2. Подключить TgNinja через закрытую группу и Bot API webhook.
3. Накопить 7–14 дней сигналов и отмечать полезные в панели — это даст данные для чистки ключевых фраз.
4. Затем подключить VK API.
5. Если публичные SearXNG дают много сбоев — добавить Brave Search API.
6. Telegram MTProto использовать только если TgNinja не покрывает нужный глобальный поиск.
7. Hunter и LLM включать после подтверждения конверсии сигналов во встречи; YouTube уже можно оставить постоянным бесплатным усилителем.
