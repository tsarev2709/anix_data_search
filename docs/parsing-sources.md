# Парсинг публичных обсуждений

Ежедневный радар сначала находит страницы через поиск и RSS, затем открывает до 12 публичных веток на `vc.ru`, `habr.com`, `reddit.com`, `pikabu.ru` и `otvet.mail.ru`. Из JSON-LD и HTML он извлекает отдельные сообщения. Если страница подгружает комментарии JavaScript и обычный HTML не дал результата, для не более трёх страниц используется Chromium/Playwright. Каждый комментарий с постоянной ссылкой оценивается существующим фильтром коммерческого спроса отдельно от текста статьи. Недатированные комментарии не попадают в очередь заявок. Статус `discussion` и ошибки видны в отчёте запуска.

Этот этап работает на существующем GitHub Actions runner без ключей и платного тарифа. Лимит меняется переменной `DEMAND_DISCUSSION_PAGES` от 0 до 30; ноль отключает этап. Он ищет только в публично доступных страницах, найденных другими провайдерами. Расписание остаётся ежедневным, скорость «30 секунд после сообщения» здесь не обещается. Сайты могут блокировать автоматический доступ или менять разметку; это отражается в диагностике, а остальные источники продолжат работу.

## Почему выбран этот способ

| Инструмент | Применение к поиску заявок Anix | Решение сейчас |
|---|---|---|
| Xmldatafeed | Мониторинг цен и ассортимента магазинов и маркетплейсов | Не подключать к радару заявок |
| A-Parser | Готовые парсеры и API собственного запущенного экземпляра | Потребуется лицензия, экземпляр и конкретный источник |
| ParseHub, Octoparse | Визуальные проекты для конкретных сайтов; облачный запуск и API зависят от тарифа | Не делать ежедневный радар зависимым от внешнего аккаунта |
| Расширения браузера | Ручной экспорт таблиц с открытой страницы | Для разовых исследований, не для фонового запуска |
| Scrapy | Каркас для отдельных Python-краулеров | Имеющийся Node crawler уже обходит sitemap/RSS/HTML, поэтому второй стек сейчас избыточен |
| Crawl4AI | Самостоятельно развёрнутый браузерный краулер | Существующий Playwright закрывает текущую задачу без отдельного Docker-сервиса |

Если появится конкретный закрытый разметкой источник, можно добавить его официальный API или отдельный адаптер и проверить правила доступа. Telegram/TgNinja в этом этапе не используется.

## Расширение охвата (AND-17, 15.10.2026)

Единый каталог `src/providers/source-catalog.ts` содержит **36 поисковых площадок**. Это адресные запросы к поисковому индексу, а не 36 готовых API-парсеров.

| Группа | Площадки |
|---|---|
| Соцсети (10) | t.me, vk.com, vk.ru, tenchat.ru, linkedin.com, threads.net, threads.com, instagram.com, ok.ru, facebook.com |
| Форумы (8) | vc.ru, habr.com, pikabu.ru, otvet.mail.ru, reddit.com, dtf.ru, searchengines.guru, forum.klerk.ru |
| Закупки (7) | zakupki.gov.ru, b2b-center.ru, fabrikant.ru, roseltorg.ru, tender.pro, tektorg.ru, etp.gpb.ru |
| Отраслевые сайты (11) | pharmvestnik.ru, gmpnews.ru, vademec.ru, medvestnik.ru, remedium.ru, sostav.ru, adindex.ru, cossa.ru, e-xecutive.ru, hh.ru, companies.rbc.ru |

Общий поиск остаётся без ограничения домена. YouTube/Rutube, новости, RSS, GitHub и официальный сайт дополняют каталог. HTML-парсер обсуждений пока работает только с пятью исходными форумами, перечисленными выше в документе. Новые площадки сначала доступны через поиск; отдельные адаптеры — бэклог.

При `DEMAND_QUERY_BUDGET=36` радар планирует 8 общих запросов о покупке, 18 отдельных `site:`-запросов, 6 новостных и 4 английских. Все 36 площадок появляются в плане за два последовательных дня. При малом бюджете квоты уменьшаются пропорционально; ротация не исключает сайт навсегда. Тематики и формулировки тоже меняются. Это гарантия плана, а не успешного доступа к сайту.

SearXNG использует до `COMPANY_QUERY_BUDGET=18` запросов на компанию (ранее 10) и `PERSON_QUERY_BUDGET=12` на человека (ранее 8). Сначала идут общие запросы, роли и программы/PDF, затем отдельные площадки с ежедневной ротацией. Отраслевой каталог или соцпрофиль не выбираются вместо официального сайта компании.

Если SearXNG не выполнил запрос, радар пробует Tavily **только при существующем `TAVILY_API_KEY`**. Лимит `DEMAND_TAVILY_QUERY_BUDGET=8` — максимум базовых API-запросов на один запуск радара, без повторных HTTP-попыток. `0` отключает резерв. Этот лимит не включает отдельный поиск контактов. Корректные пустые ответы SearXNG не повторяются; недоступные и ещё не выполненные запросы — повторяются в пределах лимита. При отказе ключа, 429 или исчерпании кредитов очередь Tavily останавливается. При частичном сбое уже найденное сохраняется. Новые платные аккаунты и подписки не создаются.

В Markdown/JSON отчёта есть `coverage`: площадки в плане, с попыткой запроса и с корректным ответом поиска, а также фактические домены результатов. Точные счётчики успешных запросов пока доступны для SearXNG/Tavily; для остальных провайдеров значение `null` («не измеряется»), а не выдуманное число. Поисковый ответ не означает чтение страницы, а дата индексации не подменяет дату публикации. Недатированные результаты по-прежнему не превращаются в прямые заявки.

### Исходная точка production

Артефакт [запуска 15.10.2026](https://github.com/tsarev2709/anix_data_search/actions/runs/38699510548) до этого изменения: 85 результатов, 85 отброшены, 0 сигналов; SearXNG/GDELT — failed; Tavily — disabled. По контактам: одна компания, 18 результатов поиска, восемь страниц, ноль кандидатов. Успешный статус Actions не означает полезный результат. После включения изменения нужен новый dry-run и сравнение (AND-8, AND-24).

Проверенный как возможный бесплатный резерв Bing RSS не подключён: на двух пробных запросах отдавал посторонние результаты, включая домены вне `site:`. Покрытие нельзя оценивать только по HTTP 200.
